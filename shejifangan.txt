在线编程机考系统基础设计方案
一、项目定位
系统定位为毕业设计，面向课堂机考与在线编程练习场景，提供：
学生在线做题和提交代码
管理员维护题库和考试
系统进行简单模拟判题
学生查看成绩和错题
系统不追求高并发和复杂安全，只保证功能流程完整、代码结构清晰、便于部署和答辩。
二、总体架构
Vue 前端
   │ HTTP/JSON
   ▼
Spring Boot 后端
   ├── Controller 接口层
   ├── Service 业务层
   ├── Mapper/DAO 数据访问层
   └── Entity 数据实体层
   │
   ▼
MySQL 数据库
技术组合：
后端：Spring Boot + MyBatis-Plus
前端：Vue 3 + Vite，沿用原生表单和现有样式（第一版不引入 Element Plus）
数据库：MySQL 8
接口风格：RESTful API
登录方式：服务端内存 Token 会话，8 小时有效，退出立即失效；后端重启后需重新登录
代码编辑器：简单文本编辑框
判题方式：本地模拟判题，不执行真实用户代码

4. 模拟判题模块
第一版不执行真实代码，只根据提交内容进行简单判断。
示例逻辑：
提交代码为空 → RE
代码包含指定关键字或标准答案片段 → AC
其他情况 → WA
判题结果：
AC：答案正确
WA：答案错误
RE：运行错误
同时返回：
判题状态
得分
简单提示
判题时间
5. 考试模块
管理员：
创建考试
设置考试名称
设置考试开放开始时间和开放结束时间（北京时间，分别录入，不由考试时长自动推算）
设置考生个人答题时长（1至1440分钟）
选择考试题目
发布或关闭考试
学生：
查看考试列表及本人每场考试的答卷状态；已完成、超时收卷或关闭收卷时显示成绩并可查看逐题详情；已关闭考试保留本人历史状态
点击“进入考试”前显示确认提示，明确说明：确认后立即开始个人倒计时，考试过程中不能主动退出或取消答题；关闭页面或断开连接不会暂停计时，重新进入可恢复答卷
确认后开始考试；取消则不创建答卷、不开始计时
限时答题
提交代码
提前交卷
自动收卷
考试开放时间范围用于判定考生是否可以进入：当前时间必须不早于开放开始时间，且早于开放结束时间。
个人答题时长从考生实际确认进入并由后端创建答卷时开始计算；个人截止时间为“个人实际开始时间 + 答题时长”和“考试开放结束时间”两者的较早值。开放时间范围与个人答题时长互相独立，允许开放窗口长于或短于个人时长。
前端倒计时基于后端返回的个人截止时间和服务器时间；后端每次运行/提交均再次校验；定时任务每10秒收取过期答卷。考试按一次连续答题流程设计，不提供暂停、撤销或常规的稍后继续模式。关闭页面、断网或重新登录不会暂停计时；如发生中断，系统恢复原答卷和原截止时间，不创建新答卷、不重置计时。该恢复机制是答卷可靠性保障，不是可选择的考试模式。
截止时只统计已经保存的提交，浏览器内未提交草稿不参与计分。
同题取有效时间内最高分，交卷后冻结成绩；未作答计0分。
“不能主动退出”表示开始后不提供取消考试、退出答卷或重置答卷的操作；学生仍可通过交卷结束答题。浏览器关闭、网络中断和重新登录不构成暂停或退出，答卷状态保留并继续按原截止时间计时。课程项目不做浏览器锁定、强制全屏、摄像监考等防舞弊措施。
考试发布后不能修改选题、时间和分值，只能关闭；关闭会收取进行中的答卷。
被考试或提交引用的题目禁止修改和删除，需要更改时新建题目版本。

十一、教师学情统计（轻量迭代）
目标与使用场景：
帮助承担管理员角色的教师快速判断“学生是否完成考试、哪些题目普遍有困难、哪些学生需要进一步辅导”。统计用于教学回顾和定位问题，不用于自动评价学生能力，也不替代教师查看具体答题记录。

调研说明：
本方案根据课程机考中常见的教学查看任务提出，尚未完成真实教师访谈或问卷，不能表述为已验证的教师调研结论。实施前可请1至3名任课教师试读指标原型，确认他们是否优先关注完成情况、题目通过情况和待关注学生，并记录反馈后微调。课程项目先按以下最小实用版本实现。

角色与权限：
第一版由现有ADMIN角色承担教师管理权限，不新增TEACHER角色、班级、课程或选课体系。只有管理员可读取统计接口和其他学生的汇总/明细；学生仍只能读取本人成绩和提交。统计范围必须由管理员指定的一场考试限定，不能默认跨考试暴露学生信息。

统计范围与指标口径：
1. 考试完成情况：展示已开始答卷数、已交卷数、进行中数、超时/关闭收卷数，以及交卷完成率。交卷完成率 = 已结束答卷数（SUBMITTED、TIMED_OUT、CLOSED）/ 已开始答卷数；未参加考试的人不在分母内，因此该指标不得称为“全班完成率”。同时展示答卷人数，避免只看百分比。
2. 题目通过情况：对考试中的每道题展示题目名称、满分、统计人数（已结束答卷数）、通过人数、未通过/未作答人数和通过率。按每位已结束答卷的该题最终有效结果计算，每名学生每题只计一次；通过定义为该题最终结果为AC且得分达到满分，其他情况（WA、RE、未作答）计为未通过。通过率 = 通过人数 / 已结束答卷人数；进行中的答卷不进入题目通过率分母。若没有已结束答卷，显示“暂无数据”，不显示为0%。
3. 待关注学生：列出已结束答卷中至少有一道题未通过的学生、考试总分、未通过题数及对应题目；未参加或仍在答题的学生不作为“错题学生”。该列表只是供教师点开成绩/提交记录进一步了解，不自动给学生贴能力标签。
4. 练习情况（后续可选）：按题目展示提交人数、通过人数和通过率。由于当前系统没有班级名单，人数仅代表至少提交过该题的不同学生；通过率分母为提交过该题的不同学生，同一学生多次提交按其是否至少有一次AC计一次。页面必须标注“参与提交学生”，不得把它解释为全班覆盖率。首轮建议先完成考试统计，练习统计待教师反馈后再决定。

数据来源与存储：
第一版复用exam_attempt、exam_result及其中每题最终明细；练习统计（若后续纳入）复用submission。统计值实时查询，不新建统计结果表、不复制保存聚合数据。成绩明细和答卷状态是考试统计的权威来源；不得通过累计原始提交次数计算考试通过人数，以免重复提交重复计数。

页面与交互：
管理员在成绩管理中选择一场考试后查看学情统计，页面分为“完成情况摘要”“题目通过情况表”“待关注学生列表”。选择学生或题目后复用现有成绩详情/提交记录查看能力。提供无答卷、无结束答卷和无错题等清晰空状态；不增加复杂图表、实时推送、跨班级筛选或自动预警。

接口建议：
新增管理员接口 GET /api/results/analytics?examId={examId}。examId必填；响应字段为 examId、examName、attemptCounts（started/completed/inProgress/submitted/timedOut/closed/completionRate）、questionStats（questionId/title/maxScore/eligibleAttemptCount/passCount/notPassedCount/passRate；eligibleAttemptCount为已结束答卷数，包含该题未作答者）、studentsToReview（userId/realName/totalScore/notPassedCount/questionIds）。完成答卷才纳入题目统计和待关注列表。非法参数返回400，不存在的考试返回404；学生访问返回403。字段定义见docs/api.md。

验收与测试：
准备一场含两道题的考试和两名学生：学生甲两题均AC并交卷；学生乙一道AC、一道WA后交卷；另安排一份进行中答卷和一名未开始考试的学生。管理员应看到已开始3份、已结束2份、进行中1份，交卷完成率为2/3；每题通过人数分别为2和1，通过率分别为100%和50%；待关注列表只出现学生乙及其未通过题。让学生重复提交同题后，统计人数不得重复增加；未交卷答卷应不进入题目通过率；学生调用统计接口应403且不能查看他人数据。补充零结束答卷、无错题、非法考试编号等边界测试，并在浏览器完成管理员查看和学生越权检查。

实施顺序与范围控制：
先向教师确认上述三类信息是否有用及“通过”的解释；再审计现有成绩明细字段能否准确区分AC、未作答和收卷状态；之后实现单场考试的管理员统计接口、页面和测试，最后按验收数据核对。首轮不改题库/判题规则，不增加班级管理、复杂报表、导出、趋势分析或预测功能；若教师确实需要“全班完成率”，应先单独设计班级/考试参与名单，不能用已提交人数冒充全班人数。
