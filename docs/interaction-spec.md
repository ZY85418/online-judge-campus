# 页面交互详细方案

版本：v2.0
日期：2026-10-09
适用范围：Campus Judge 学生端、管理员端
依据：`shejifangan.txt`、`docs/api.md`、`docs/current-status.md`

本文是页面开发和验收依据，规定页面的任务、信息层级、操作入口、状态、反馈和返回关系。它不改变后端权限、考试计时、成绩计算或模拟判题规则。

## 一、统一交互规则

### 1. 页面结构

每个业务页按固定顺序组织：

1. 页面标题和一句用途说明。
2. 查询区或操作区。
3. 加载状态、结果数量或当前筛选说明。
4. 列表/表格。
5. 空状态、错误状态和分页。

列表页默认显示列表；新增和编辑使用独立表单。保存成功后返回原列表，并保留查询条件和页码；取消编辑也返回原列表，不丢失筛选条件。

### 2. 查询规则

所有具有筛选条件的页面必须提供“查询”按钮。输入或选择条件后，只有点击“查询”才更新查询结果；回车与点击按钮行为一致。点击查询时回到第一页，并在列表上方显示当前有效条件。

“清除条件”清空所有筛选项、回到第一页并立即显示完整列表。查询期间按钮禁用并显示“查询中…”。查询失败时保留条件和已有列表，显示“查询失败，请重试”，不能显示成空列表。

纯本地过滤页面也必须提供查询按钮，以保持题库、考试管理和其他列表的操作一致；查询按钮只触发本地筛选，不新增接口参数。

### 3. 列表规则

- 表头使用业务名称，不显示内部字段名。
- 每行操作只针对当前行对象，按钮旁不依赖用户猜测上下文。
- 删除、关闭考试、开始考试、交卷等有后果的动作必须二次确认。
- 空数据与筛选无结果使用不同文案：前者说明尚无数据，后者说明没有符合条件的记录并提供清除条件。
- 加载中不重复发起请求；迟到响应不得覆盖新查询、新账号或新考试状态。
- 时间统一显示“北京时间”，列表时间格式为`YYYY-MM-DD HH:mm`。

## 二、学生端

### 1. 登录和注册

登录页只保留登录必需字段。处理中禁用提交按钮。登录失败保留用户名并清空密码；注册成功但自动登录失败时显示明确提示，允许重新登录且不重复注册。退出后清空用户名、密码、注册姓名、页面数据和本地会话。

### 2. 题库

题库查询区包含：题目关键词、分类、难度、“查询”和“清除条件”。关键词匹配标题或描述，忽略首尾空格；查询后显示“共 X 道题目”。列表列出题号、标题、分类、难度、分值和“开始作答”。

打开题目后显示题面、样例、代码编辑区和“运行”“提交判题”。返回时回到题库原筛选条件和页码。提交成功显示提交编号；提交成功但记录刷新失败时必须提示“提交已成功，记录刷新失败”，不能让用户重复提交。

### 3. 考试中心

学生考试中心只展示与本人相关的信息：考试名称、开放时间、个人答题时长、本人答卷状态、成绩和操作。状态必须区分：未开放、开放中、已结束、进行中、已完成、超时收卷、关闭收卷和未参加。

进入考试前显示确认框，说明立即开始个人计时、关闭页面不会暂停、不能取消或重置。取消不调用开始接口。进行中答卷显示“答题进行中”或“恢复答卷”，不得创建第二份答卷。终态显示“查看成绩”。

### 4. 成绩与错题

学生只能看到本人已结束成绩。查询区可按考试筛选，并提供“查询”按钮；错题过滤属于当前结果的本地显示条件，也应提供明确的“应用筛选/刷新成绩”操作。成绩详情显示考试名、总分、交卷时间、逐题结果、得分、未答题和提交代码入口。

## 三、管理员端

### 1. 管理员导航

管理员不使用学生专属的“个人考试中心”完成管理任务。管理员导航保留：题库管理、考试管理、成绩与错题、提交记录、学生管理和个人信息。

如保留“考试中心”用于查看整体状态，必须显示考试状态而不是“未参加”，并禁止显示学生进入、恢复和个人成绩操作。推荐将考试状态直接放入考试管理列表，减少重复入口。

### 2. 题库管理

默认进入题目列表，查询区包含关键词、分类、难度、状态、“查询”和“清除条件”。列表列出题号、标题、分类、难度、分值、状态和操作。

每行提供“编辑”“删除”。引用考试或提交记录的题目由后端拒绝修改/删除，前端保留表单或列表条件并显示原因。新建和编辑表单提供“返回题目列表”“保存题目”；保存成功返回原列表。

### 3. 考试管理

默认进入考试列表，查询区包含考试名称/编号、状态、“查询”和“清除条件”。列表列出编号、名称、开放开始/结束时间、个人答题时长、题目数、考试状态和操作。

每场考试必须有编辑入口，但按钮状态遵循业务规则：

| 考试状态 | 编辑 | 其他操作 |
| --- | --- | --- |
| 草稿 | 可编辑，可发布 | 无关闭必要 |
| 已发布且未到结束时间 | 禁用 | 可关闭并确认收卷 |
| 已发布且已结束、无答卷/提交 | 可编辑 | 可关闭 |
| 已发布且已有答卷/提交 | 禁用 | 可关闭 |
| 已关闭 | 禁用 | 显示已关闭 |

编辑按钮禁用时应显示原因，例如“考试已产生答卷，不能修改历史规则”。后端必须再次校验，不能依赖前端按钮。

考试编辑表单包含名称、开放开始时间、开放结束时间、个人答题时长、状态和题目选择。时间校验失败应指出具体原因；保存失败保留全部输入；关闭考试前说明会收取进行中答卷。

### 4. 成绩与学情统计

管理员成绩页查询区包含学生编号、考试和“查询”。点击查询后显示当前筛选、已交卷人数和平均分。选择考试后通过独立按钮查看学情统计，不因选择下拉项自动请求。

统计页面按“完成情况摘要 → 题目通过情况 → 待关注学生”排列，并明确完成率和通过率分母。待关注学生可进入成绩明细；返回后保留原考试选择和筛选。

### 5. 提交记录

管理员提交记录查询区包含学生编号、考试编号、题目编号、结果和“查询”“清除条件”。列表显示提交编号、学生、题目、考试、结果、得分和提交时间。代码正文只能通过提交编号打开详情；返回详情后恢复原筛选条件。

页面必须说明当前最多展示最近200条，不能把列表数量称为全部历史记录。学生提交记录只显示本人，后端负责权限限制。

### 6. 学生管理

查询区包含用户名/姓名关键词、学生编号、账号状态、“查询”“清除条件”。点击查询后回到第一页，显示总数和当前页。每行提供“查看详情”，详情显示账号摘要、考试答卷摘要和最近提交摘要；不显示密码，不提供越权修改入口。

## 四、统一状态反馈

| 场景 | 页面行为 |
| --- | --- |
| 首次加载 | 显示加载中，不立即显示“暂无数据” |
| 查询中 | 禁用查询按钮，保留旧列表直到新结果返回 |
| 无数据 | 显示“暂无记录”及下一步提示 |
| 筛选无结果 | 显示“没有符合条件的记录”和清除条件按钮 |
| 请求失败 | 保留已有数据和筛选条件，显示失败原因及重试入口 |
| 保存成功 | 显示对象名称和操作结果，返回原列表 |
| 权限不足 | 显示无权限，不能只依赖隐藏按钮 |
| 会话失效 | 清空当前页面数据并返回登录页 |
| 危险操作 | 说明具体对象、后果和取消选项 |

## 五、页面验收场景

1. 在题库输入关键词、选择分类和难度，点击查询，确认结果、数量和第一页正确；清除后恢复全部题目。
2. 在考试管理搜索指定考试，切换状态筛选，确认查询按钮后结果才变化；编辑草稿并返回，条件和页码保留。
3. 对已结束且无历史记录的考试执行编辑；对开放中或已有答卷的考试点击编辑，确认按钮禁用且原因清晰。
4. 管理员进入任何考试相关页面，不出现“未参加”个人状态；学生进入考试中心能看到自己的答卷状态。
5. 成绩、提交记录和学生管理分别查询，确认一个页面的失败不会清空其他页面的数据。
6. 查询无结果、接口失败、重复点击、返回列表、退出登录后重新进入，均检查空态、错误提示、条件保留和数据隔离。

## 六、范围边界

本方案不新增班级体系、复杂图表、导出、实时推送、真实代码执行、监考或高并发架构。新增接口、数据库字段或业务规则时，必须同步更新设计方案、API 文档、验收清单和当前基线。

## 七、本轮落地与边界（2026-10-09）

- 学生题库、管理员题库、考试管理和学生管理已分离待输入条件与已查询条件；更改字段不修改列表，点击查询/回车才应用，清除立即恢复。翻页仍使用已查询条件。
- 管理员侧栏隐藏学生考试中心入口，保留考试管理；成绩入口命名为“学生答卷与成绩”。该页面先展示答卷摘要表（姓名、账号、学生编号、考试、总分、收卷时间），点击“查看答卷”进入一份答卷的逐题结果和保存代码入口，返回列表保留当前结果。
- 答卷列表目前只包含已结束且已生成成绩的答卷，进行中答卷仍通过学生管理/单场学情统计查看；未作答题目没有代码入口。
- 上述行为已实现并有自动化验证；本文其他目标不能因此视为全部实现。例如学生成绩考试筛选、代码详情返回后的完整组件状态恢复仍需后续单独评估。


### 学生提交记录优化（2026-10-09）
学生提交记录页提供考试、题目关键词和判题结果筛选；条件仅在点击“查询”后生效。列表展示提交编号、题目名称、考试名称、结果、得分、判题耗时和北京时间提交时间。提交编号进入代码详情，返回时保留列表上下文。无匹配时显示“没有符合条件的提交记录”。学生筛选使用已加载的本人记录，不新增接口，也不改变后端本人权限。
