### 体验是否合理的判定

自动化测试验证规则和状态，不能单独证明交互方便。列表类目标至少使用少量数据和较多数据各走一遍任务；由未参与开发的使用者尝试“按题目描述找到指定题目”“翻到指定页后打开目标题”“编辑指定题目”“确认后一次完成考试”“中断后恢复原答卷”“查看已完成考试的某题提交代码”。记录是否需要口头提示、是否误点、是否找错状态或无法返回。若任务失败或需要解释页面术语，应先修订交互说明和验收条件，再判断实现通过。当前尚无本轮真实用户试用记录，体验合理性未验证。

自动化覆盖：`ApiAuthorizationTest` 是 MockMvc 权限及参数测试；`ExamWorkflowTest` 使用 H2 数据库真实事务验证考试开始窗口、个人截止时间、最高分、重复/并发交卷、过期扫描、关闭和失败回滚；前端 Node 测试覆盖草稿恢复、认证状态、时间解析与校验、考试可进入状态、逐场答卷状态映射和确认/取消入口策略。H2 结果不等同于 MySQL 部署验收，需另保留本机联调记录。浏览器操作的确认框与按钮状态需在浏览器验收；自动化测试不替代浏览器实际操作验收。

限制：不执行真实用户代码；浏览器草稿只在当前浏览器保存；截止时仅统计已提交数据；Token在后端内存，重启后需重新登录，考试状态与成绩保存在数据库。

## 查询提交与管理员答卷识别验收

1. 改变题库分类/难度或考试状态，列表与页码保持不变；点击查询或回车才更新结果并回到第一页。清除条件恢复完整结果。
2. 学生管理编辑关键词不自动请求；查询后再编辑输入并翻页，仍使用上次已查询的条件。
3. 管理员无学生考试中心导航，使用考试管理维护考试；在学生答卷与成绩中可区分两名学生的姓名、账号、编号及成绩，分别打开答卷查看逐题结果和对应代码。
4. 学生成绩仍限本人；管理员成绩响应只补充用户标识摘要，不得包含密码。
